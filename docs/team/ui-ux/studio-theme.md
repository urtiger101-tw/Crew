# Studio theme: design and verification

Reference: `C:/Users/eda/Downloads/Screenshot_2026-11-02-13-11-49-211_com.facebook.katana.jpg` (a dark, restrained IDE workspace). The terminal-native adaptation uses a charcoal pane and quieter bars, thin separators, and the existing optional right-hand agents sidebar. It does not add a file browser or imitate window controls. Child applications retain explicitly selected ANSI and RGB colors; `terminal`, `dark`, `light`, and `mono` retain their prior default pane colors. `studio` supplies defaults for otherwise-default pane colors, with `NO_COLOR`/`TERM=dumb` restoring terminal defaults. Sidebar and pane colors can be overridden through theme tokens.

Verification: the `studio_` unit tests cover the default theme, sidebar fill, monochrome and ASCII behavior, status focus, and mixed default/ANSI/RGB VT cells. The render suite covers layout, copy labels, and ANSI encoding; the existing selection inversion path is unchanged. The integrated Windows run passed 540 unit tests and 21 integration tests, with the desktop clipboard test and one pre-existing host-loss boundary ignored in the default suite. The clipboard test was separately run against an actual copied image and passed.

Live visual check (2026-11-02): opened an isolated Windows Terminal client with the studio theme, a 24-column sidebar, and Traditional Chinese labels. The verification launcher cleared inherited `NO_COLOR=1` and changed `TERM=dumb` to `xterm-256color` only for this test client; a preceding monochrome capture confirmed that those environment settings remain honored. Ctrl+Alt+V was dispatched to the actual window and inserted a PNG path without Enter; decoded pixels exactly matched the 1483 x 762 source. The original clipboard was restored. Varied host themes, DPI scaling and mouse interactions remain **NOT_RUN**.
