# Crew 0.6.0 — Agent recovery and terminal UX

2026-11-02 · Windows x86_64 MSVC · Local build

## Changes since v0.5.1

- Restore saved agent identity and resume argv without running them automatically.
  Use `crew pane resume pN` or `prefix R`; repeated requests do not resubmit.
  Pending panes show their state and saved command; duplicate names suggest attach.
- Draw a thin separator immediately below the toolbar. F1 toggles both rows,
  `prefix ?` opens help, and narrow layouts keep at most six toolbar buttons.
  Every pane gets a title by default, focused edges are clearer, automatic window
  names include agents, and status counts use readable labels.
- Add `crew doctor [--json]` for the connected daemon executable, PID, version,
  start time and color environment hazards. Pane color isolation and per-client
  chrome color settings retain explicit user overrides.
- Add the charcoal studio theme and Windows clipboard image paste without an
  additional package. Preserve native PNG bytes and transparency where available.
- Improve Windows UTF-8 console setup, Ctrl-C delivery, restart/nesting detection,
  wide-cell rendering and host-lost pane handling. Add scrollback keys and MRU
  window switching. Chrome preserves emoji ZWJ and rejects terminal controls.
- Report missing Windows shells before the UTF-8 helper starts. If opening a new
  worktree fails, retain its completed checkout and return the failure to the caller.
- Add agentcmd PATH plugins, Codex progress/terminal-title display, the durable
  `peer`/`msg` inbox, and bounded worker-bootstrap/Claude Stop receiver helpers.
- Retire `tmuxlike.exe` and `TMUXLIKE*` variables. Use `crew`; the default socket
  is `crew-<user>.sock`. Existing live daemons are not automatically restarted.

## Known issues and validation limits

- **U1 remains a known issue:** Claude Code input can have missing or overlapping
  Chinese text. Programmatic short and wrapped split-pane edit/replay checks did
  not reproduce it. **Windows IME preedit and native visual behavior are not
  verified.** The user explicitly authorized publication with this limitation.
- **U4/U5 deferred:** the new reliable `pane submit` operation and unified lifecycle
  semantics are not implemented. Existing API state names/authority are retained.
- **Hosted CI was not run.** Both hosted CI and Release workflows remain disabled.
  Local native command results and source/binary digests are recorded in the
  attached `windows-native-summary.json` and `release-manifest.json`.
- The unsigned Inno Setup installer is compiled and payload-verified, but its
  full installation/upgrade/downgrade/uninstall lifecycle is **not certified**.
  The earlier pinned Crew 0.3.0 compatibility fixture was denied by Windows App
  Control (WinError 4551). That denied operation is not retried or bypassed;
  full installer lifecycle remains blocked and is not reported as PASS.
- Linux/macOS native execution and the cross-platform matrix are **NOT_RUN**.
  An ignored host-loss regression records the known case where both console host
  and shell die before Crew has observed a surviving child.

This is an explicitly authorized manual local release. It does not claim that
`package_local.py`'s complete-evidence gate or hosted release provenance passed.
The native summary is an honest coverage report, not a substitute for those gates.

## Assets

The asset set matches v0.5.1: Windows portable ZIP and JSON sidecar, unsigned
setup EXE and JSON sidecar, the native summary, release manifest and
`RELEASE-SHA256SUMS`. The portable payload contains `crew.exe`, README, LICENSE
and its embedded manifest. Verify the published SHA-256 values before use.

Extract the ZIP to a new directory or use the per-user installer. The installer
does not automatically modify PATH. Preserve your existing configuration/state;
shared-daemon replacement is a separate manual action.
